## 结论摘要

| 层级 | 结果 | 严重度 |
|------|------|--------|
| 策略代码层 | ✅ 9/9 无 shift(-n) 未来数据引用 | 无 |

## 🔴 核心发现：盘中 vs 收盘 时点不一致（系统性偏差）

### 机制

```
新浪K线接口(盘中实时更新当日K线)
    ↓
DataManager.fetch_stock_history()  ← 无当日截断
    ↓
engine_mixin._scan_signals()  ← 盘中每5分钟跑
    ↓
signal_pipeline.process(df)   ← 策略用"未完成当日K线"计算信号
    ↓
signal["is_intraday"]=True    ← 只打标记，不隔离
```

### 问题本质

- **回测**：用收盘后完整K线计算信号（当日 high/low/close 是最终值）
- **盘中实盘**：用未完成K线计算信号（当日 high/low/close 是盘中瞬时值）
- **结果**：同一策略，盘中触发的信号 ≠ 回测中会触发的信号 → **实盘信号无法用回测统计验证**

### 受影响的策略（全部9个已启用策略）

| 策略 | 盘中风险点 |
|------|-----------|
| box_breakout | `close > box_high`（当日close是盘中价） |
| rsi_reversal | `rsi >= oversold`（rsi含当日close） |
| double_yin | 当日K线阴阳/缩量判断（当日未完成） |
| chenxuezhang | 当日量价规则 |

| price_volume_signal | 当日量比/价格 |

| death_valley_rebound | 当日超跌判断 |
| bollinger_oversold_rebound | 当日布林位置 |

## ✅ 已排除的风险

1. **策略代码无未来数据**：9/9 无 `shift(-n)`、无未来索引（静态扫描确认）
2. **`shift(1)` 是正确用法**：前一日本来就已知，非前视
3. **回测本身无前视**：断板反包事件研究已用"次日开盘入场"口径

## 修复建议（按优先级）

### P0: 盘中扫描隔离当日K线
在 `_scan_signals` 中，盘中时段（非收盘后）从 df 剔除最后一行（当日未完成K线），让策略只基于已收盘历史K线计算形态：
```python
# engine_mixin.py _scan_single 中, 盘中时:
if is_trading_time() and not is_after_close():
    df = df.iloc[:-1].copy()  # 剔除当日未完成K线
```
代价：盘中信号会延迟到收盘后形态确认（或盘中只看已收盘形态），但信号与回测口径一致。

### P1: 盘中信号标记 + 收盘确认
盘中信号保留但标注 `pending_close_confirm`，收盘后（15:00）重新验证是否仍成立，只推送确认后的信号。

### P2: 建立"信号时点审计"CI
- 静态检查：策略代码禁止 `shift(-n)`（已确认无）
- 动态检查：实时扫描信号 vs 收盘重算信号的一致性率，低于阈值告警

## 影响评估

- **对断板反包**：scan_rebound_market.py 是独立盘后脚本（15:00），无此问题 ✅
- **对 gugu 主链路**：9个启用策略全部受影响，信号可信度存疑，绩效回填的"信号"与盘中实际推送不一致
