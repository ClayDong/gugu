# 迭代 9：炒股专家审查修复（v0.3.8）

> 从炒股专家第一性原理视角审查项目，识别并修复 8 个关键问题。

## 背景

用户要求从炒股专家视角审查项目，发现以下核心问题：

1. **尾盘选股器逻辑是"高位接盘"**：筛选涨幅 3-5% 的股票 = 次日回调概率大
2. **移动止损递减漏洞**：A 股主力用"跌停板吃货→拉升诱多→再下跌"手法，递减逻辑导致永远触发不了 3 次清仓
3. **双均线假信号泛滥**：A 股 70% 时间震荡，原金叉死叉频繁假信号是亏损机器
4. **资金流默认放行**：数据缺失时默认 pass = "不知道有没有主力流入就买入" = 盲目进场
5. **持仓时间无风控**：阴跌股套牢——不触发止损但持仓 3 个月亏 20%
6. **大市过滤只看沪深300**：2024 年小盘股暴跌时沪深 300 仍上涨 → 误判"牛市可买"
7. **缺少周复盘推送**：新手最大问题是不复盘

## 修复清单

|---|--------|------|----------|

| P0-2 | P0 | 移动止损去掉递减 + 创新高重置 + 放量跌破直接 EXIT | `analysis/trailing_stop.py` |

## 关键设计决策

### P0-1：缩量回踩低吸逻辑

原逻辑筛选"涨幅 3%-5%"的股票 = 高位接盘，次日回调概率大。
改为 8 条件低吸逻辑：

1. 当日涨幅 -2% ~ +1%（回踩而非追涨）
2. 前 5 日内有涨幅 ≥5% 的强势表现
3. 当日缩量（量比 < 1.0）
4. 收盘价 ≥ MA20（趋势未破）
5. MA20 > MA60（中期趋势向上）
6. 换手率 3%-15%
7. 流通市值 50 亿-500 亿
8. 回踩日不异常强势

### P0-2：移动止损重设计

**原问题**：递减逻辑（价格回升浪谷 2% → 计数 -1）被主力诱多利用。

**修复**：
- 去掉递减逻辑
- 仅当价格真正创新高（`current_price >= state.highest_price`）时才完全重置计数为 0
- 新增：跌破浪谷时若当日放量（量比 ≥ 1.5），直接 EXIT（不必等 3 次）

### P0-3：双均线假信号过滤

**原问题**：A 股 70% 时间震荡，金叉死叉频繁假信号。

**修复**：金叉买入需同时满足：
1. 金叉（MA short 上穿 MA long）
2. 量比 ≥ 1.5（成交量确认）
3. MA20 > MA60（中期趋势向上）
4. MA20 斜率 > 0（趋势方向向上）

通过 `params` 可配置关闭（`volume_confirm=False`, `trend_filter=False`），用于回测对比。

### P1-4：资金流默认拒绝

数据缺失时改为默认拒绝（`pass=False`），仅 `signal_only` 模式放行。

### P1-5：持仓时间风控

- 持仓 30 天未盈利 → 警告减半仓
- 持仓 60 天未盈利 → 强制清仓

### P1-7：多指数大市过滤

增加中证 500 + 创业板指校验：
- 两个中小盘指数中至少 1 个在 MA200 之上才算中小盘可买
- 三级冗余：akshare → 新浪 → 东方财富

### P2-8：周复盘推送

周日 20:00 汇总本周信号统计，推送飞书复盘卡片。

## 深度反思

### 为什么 P0-1 是最重要的修复

原尾盘选股器逻辑是"涨幅 3-5% 追涨"，这违反了《炒股的智慧》的核心原则——"不追高"。新手最大的亏损来源就是追涨杀跌，系统却在自动化这个错误。

### 为什么 P0-2 的递减逻辑必须去掉

A 股主力的典型手法：
1. 跌停板吃货（跌破浪谷 1 次 → 计数 1）
2. 拉升诱多（价格回升浪谷 2% → 计数递减回 0）
3. 再下跌（跌破浪谷 1 次 → 计数 1）
4. 循环 1-3，永远触发不了 3 次清仓

去掉递减后，只有真正创新高才重置，主力诱多无法重置计数。

### 为什么 P0-3 要加成交量确认

A 股震荡市中，MA 金叉假信号频发。加入成交量确认（量比 ≥ 1.5）可以有效过滤无量的假金叉。同时 MA20 > MA60 确保中期趋势向上，避免在下跌趋势中抢反弹。
