> 记录 gugu 项目的重要架构决策、权衡和理由。
> 遵循"第一性原理"原则：每个决策从问题本质出发，不因惯例照搬。

## ADR-001: 信号监控优先而非自动交易

**状态**: 已采纳（2026-07-06）
**影响范围**: 全局架构

### 背景
系统默认 `signal_only` 模式，只推送信号不下单。

### 决策
- 默认模式为信号监控 + 绩效验证
- paper/live 模式为可选进阶
- signal_only 模式下跳过 Wisdom LLM 调用，但仍执行硬编码 fallback 获取止损/止盈/仓位建议

### 理由
1. **风险控制**：自动交易需要经过充分验证，信号监控阶段收集实际数据
2. **渐进式验证**：五阶段架构（策略固化→回测→信号监控→模拟盘→实盘）不可跳级
3. **用户自主权**：个人投资者保留最终决策权

### 后续优化
- signal_only 模式卡片添加"仅通知，不构成交易建议"免责声明（v0.6.0）

## ADR-002: 自研轻量引擎而非 qlib

**状态**: 已采纳
**影响范围**: backtest/、analysis/

### 背景
需要回测和绩效分析能力，但 qlib 依赖重（PyTorch、GPU）。

### 决策
自研轻量回测引擎，不引入 qlib 重依赖。

### 理由
1. **依赖轻量**：避免 PyTorch 等重依赖
2. **定制灵活**：A 股特有规则（T+1、涨跌停、手续费）可精确实现
3. **性能足够**：个人使用场景下自研引擎性能满足需求

### 参考
- `src/gugu/backtest/engine.py` — 自研回测引擎
- `src/gugu/analysis/performance.py` — Brinson 归因 + 因子归因

## ADR-003: 三级数据源冗余

**状态**: 已采纳
**影响范围**: data/collectors/

### 背景
免费 API（akshare/东方财富）不稳定，经常被限流或返回空数据。

### 决策
三级数据源冗余 + 自动降级：
- 主源：sina（实时行情）
- 第一降级：akshare（东方财富后端）
- 第二降级：东方财富 push API 直连（httpx）

### 理由
1. **高可用**：单源故障不影响系统运行
2. **免费**：不依赖付费数据源
3. **自动降级**：主源连续失败 3 次后自动并发降级，冷却 5 分钟后切回

### 后续优化
- 资金流 API 不可用时用量价推算 fallback（v0.5.4）
- HTTP 重试 + UA 池轮换防限流（v0.5.4）

## ADR-004: 飞书作为唯一通知渠道

**状态**: 已采纳
**影响范围**: notifier/

### 背景
需要实时通知策略信号和风控告警。

### 决策
仅支持飞书开放平台卡片消息，不引入多渠道。

### 理由
1. **个人使用**：开发者日常使用飞书
2. **卡片消息丰富**：支持 markdown、交互按钮、颜色模板
3. **API 稳定**：飞书开放平台 API 成熟

### 权衡
- 添加新渠道需要修改 FeishuNotifier 接口
- 飞书 API 限流（QPS 限制）需要重试队列

### 后续优化
- 通知重试队列持久化到 JSONL（v0.5.0）
- 指数退避重试策略（v0.6.0）

## ADR-005: 十大视角评分系统而非单一模型

**状态**: 已采纳（v0.5.0）
**影响范围**: analysis/perspectives/

### 背景
需要多维度评估股票质量，而非单一技术指标或基本面模型。

### 决策
将 10 位投资大师的认知框架量化为独立评分函数（0-10 分），加权汇总。

### 理由
1. **可解释性**：每个评分附带推理链，用户可理解评分依据
2. **模块化**：每个视角独立，可单独启用/禁用/调整权重
3. **木桶效应**：最低分视角决定整体判定，避免单一维度掩盖致命缺陷
4. **无外部依赖**：纯计算函数，无需 LLM 或外部 API

### 架构
```
analysis/perspectives/
├── data_types.py    # StockDataContext, PerspectiveScore, PerspectiveAnalysisResult
├── scorer.py        # 10 个评分函数
├── engine.py        # PerspectiveEngine（单股/批量分析）
└── integrators.py   # 与现有模块的集成桥接
```

### 后续优化
- 技术指标计算缓存（v0.6.0 计划）
- 评分函数单元测试增强（v0.6.0）

## ADR-006: 熔断状态持久化

**状态**: 已采纳（v0.5.0）
**影响范围**: risk/manager.py

### 背景
进程重启后熔断状态丢失，可能绕过 L2 日亏熔断铁律。

### 决策
熔断状态持久化到 `data/risk_state.json`，使用原子写入。

### 理由
1. **铁律不可绕过**：进程重启不应重置熔断状态
2. **原子写入**：防止崩溃导致文件截断
3. **跨日自动失效**：仅恢复当日熔断状态，跨日熔断自动失效

### 权衡
- 文件损坏时保守恢复为非熔断状态（误熔断影响 > 漏熔断）
- 人工可手动删除文件解除熔断（需物理访问服务器）

## ADR-007: 信号过滤链的"沉默拒绝"修复

**状态**: 已采纳（v0.6.0）
**影响范围**: engine/main.py、notifier/formatter.py

### 背景
信号在过滤链中被拒绝时仅记录日志，用户不知道系统在做什么。

### 决策
在收盘报告中展示当日被过滤的信号摘要，包含股票、方向、过滤原因。

### 理由
1. **透明度**：用户了解系统决策过程
2. **可调试**：用户可判断过滤规则是否合理
3. **低开销**：仅收集摘要信息，不增加额外 I/O

### 实现
- `TradingEngine._collect_filtered_signals()` 收集被过滤信号
- `DailyReportManager.send_report()` 接收过滤信号参数
- `formatter._format_filtered_signals()` 格式化展示

## ADR-008: 技术指标统一计算

**状态**: 已采纳（v0.6.0）
**影响范围**: analysis/technical.py

### 背景
多个模块（stage_detector、perspectives、alpha_factory）各自实现技术指标计算，存在重复和差异。

### 决策
在 `technical.py` 中集中提供所有常用技术指标计算，各模块通过此模块获取。

### 理由
1. **消除重复**：ATR/RSI/MACD/布林带等指标只需实现一次
2. **一致性**：所有模块使用相同的计算方法，避免结果差异
3. **可测试**：集中测试指标正确性

### 当前指标
- `atr()` — 平均真实波幅
- `sma()` / `ema()` — 移动平均
- `rsi()` — 相对强弱指标（Wilder 平滑）
- `macd()` — 异同移动平均线
- `bollinger()` — 布林带
- `obv()` — 能量潮

## ADR-009: 并发预取与评分

**状态**: 已采纳（v0.6.0）
**影响范围**: engine/main.py、analysis/stock_ranker.py

### 背景
扫描多只股票时串行 I/O 等待导致整体耗时过长。

### 决策
使用 `asyncio.gather` + `Semaphore` 限制并发数，批量预取和评分。

### 理由
1. **I/O 密集型**：数据采集是 I/O 密集型操作，并发可大幅缩短时间
2. **资源控制**：Semaphore 限制并发数，避免过载数据源
3. **异常隔离**：单只股票失败不影响其他股票

### 实现
- `TradingEngine._scan_signals`：批量预取历史数据使用并发
- `StockRanker.rank`：多只股票评分使用并发

## ADR-010: 通知重试指数退避

**状态**: 已采纳（v0.6.0）
**影响范围**: notifier/feishu.py

### 背景
飞书 API 限流时，固定 2 分钟重试可能加剧问题。

### 决策
根据重试次数实现指数退避：第 0 次立即重试，之后每 `2^retry_count` 次触发一次。

### 理由
1. **减少限流**：退避策略降低重试频率，避免触发飞书 QPS 限制
2. **最终送达**：重试次数超限时通过 webhook 发送告警
3. **过期清理**：超过 24 小时的条目自动丢弃（昨日信号今日已无意义）

### 退避策略
| 重试次数 | 触发频率 | 实际间隔 |
|----------|----------|----------|
| 0 | 每次 | ~2min |
| 1 | 每2次 | ~4min |
| 2 | 每4次 | ~8min |
| 3 | 每8次 | ~16min |
| ≥5 | 永久丢弃 | — |

## ADR-011: 调度任务可配置化

**状态**: 已采纳（v0.6.0）
**影响范围**: config/settings.yaml、scheduler.py

### 背景
每天 20+ 次推送存在信息过载，用户无法关闭不需要的推送类型。

### 决策
在 `settings.yaml` 中新增 `scheduler.tasks` 区块，提供 20 个任务开关。

### 理由
1. **用户自主权**：用户可根据需求关闭不需要的推送
2. **向后兼容**：配置不存在时默认启用所有任务
3. **强类型**：`SchedulerTasksConfig` Pydantic 模型提供类型安全和默认值

### 实现
- `_task_enabled()` 方法读取配置，不存在时返回 True
- 每个 `add_job` 调用前检查开关
- 修改配置后无需重启（配合 ADR-012 热加载）

## ADR-012: 配置热加载

**状态**: 已采纳（v0.6.0）
**影响范围**: config/__init__.py、scheduler.py

### 背景
修改策略参数或调度配置后需要重启 scheduler，影响盘中交易。

### 决策
提供 `refresh_config()` 和 `config_has_changed()` 接口，scheduler 每 5 分钟检测文件变更自动重载。

### 理由
1. **零停机**：配置修改后无需重启服务
2. **低开销**：基于文件 mtime 比较，无 I/O 开销
3. **安全**：仅刷新配置缓存，不修改运行中的任务（任务变更需下次 setup）

### 实现
- `get_config.cache_clear()` 清除 LRU 缓存
- `config_has_changed()` 比较 `settings.yaml` 的 `st_mtime`
- scheduler 每 5 分钟执行 `_safe_check_config`

## ADR-013: 尾盘选股器接入十大视角评分

**状态**: 已采纳（v0.6.0）
**影响范围**: screener/terminal_screener.py

### 背景
尾盘选股器仅基于技术指标（MA20/量比/换手率），缺少基本面和质量维度的评估。

### 决策
对通过筛选的股票附加十大视角评分，排序时视角评分优先于涨幅。

### 理由
1. **多维度评估**：技术指标 + 基本面 + 资金流 + 板块热度综合评分
2. **低开销**：仅对通过筛选的少量股票（≤10 只）运行评分
3. **可扩展**：评分结果存储在 `ScreeningResult.perspective_score`，通知卡片可展示

### 实现
- `_score_with_perspectives()` 方法复用已有 K 线数据
- 排序逻辑：视角评分降序 → 涨幅升序

## ADR-014: 数据源健康监控

**状态**: 已采纳（v0.6.0）
**影响范围**: web/app.py

### 背景
数据源（sina/akshare/东方财富）不稳定，但用户无法直观了解各通道状态。

### 决策
在 `/api/health` 端点中返回三通道数据源状态 + 资金流状态。

### 理由
1. **可观测性**：用户可直观了解各数据源可用性
2. **快速排障**：数据源故障时可快速定位问题通道
3. **低开销**：基于已有状态信息，无需额外采集

### 返回格式
```json
{
  "data_sources": {
    "primary": {"name": "sina", "status": "active", "error_count": 0},
    "fallback": {"name": "eastmoney", "status": "active", "error_count": 0},
    "secondary": {"name": "akshare", "status": "unknown", "error_count": 0}
  },
  "flow_source_status": "active|unavailable|partial"
}
```
