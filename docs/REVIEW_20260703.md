## 已修复问题（审查中发现并修复）

### P0-1 [风控官] 买入信号优先于卖出信号违反风控原则 ✅ 已修复

**问题**：原代码 `df.loc[sell_cond & ~buy_cond, "signal"] = -1` 使得同时满足买卖条件时买入优先，违反"风控优先"原则。

**修复**：改为 `df.loc[sell_cond, "signal"] = -1`，卖出信号覆盖买入信号。

**第一性原理**：趋势破坏时不应入场，即使出现放量确认信号。风控 > 入场机会。

### P0-2 [系统架构师] 策略未加入 settings.yaml enabled 列表 ✅ 已修复

**问题**：策略在 `_REGISTRY` 和 manifest 中注册，但 `settings.yaml strategy.enabled` 未包含 `money_flow_follow`，导致 `get_enabled_strategies()` 不会加载它。

**修复**：在 `settings.yaml` 的 `strategy.enabled` 列表中添加 `- money_flow_follow`。

### P1-1 [数据工程师] 置信度计算 NaN 传播 ✅ 已修复

**问题**：`vol_ratio_today = volume / volume.shift(1)` 在停牌后复牌可能导致除零或 NaN，传播到 confidence 列。

**修复**：在 confidence 计算末尾添加 `.fillna(0.0)`。

## 遗留问题与改进建议

### P1 级 — 建议修复

#### P1-1 [量化研究员] "热点板块"近似方法存在偏差

**问题**：用户笔记强调"板块行情中跟随资金强度"，策略用 `recent_gain >= 3%`（个股涨幅）近似"热点板块"，但个股涨幅 ≠ 板块涨幅。策略可能选出独立上涨的妖股而非板块联动股。

**影响**：在非板块行情中可能误判为"热点"。

**建议**：
- 方案 A（推荐）：在 `SignalRouter.route()` 中注入板块信息，策略可访问所属板块涨幅
- 方案 B：在选股层（`stock_selector.py`）先用 `SectorRotation.detect()` 筛选热点板块，再对板块内个股运行策略
- 方案 C（最小改动）：保持现状但在文档中标注此近似方法的局限性

**当前状态**：方案 C（已标注），因 SignalRouter 接口仅接受 DataFrame，注入板块信息需改接口。

#### P1-2 [交易员] 跌破 MA20 即卖出可能过于敏感

**问题**：`below_ma20 = df["close"] < ma20` — 单日收盘跌破 MA20 即卖出，可能在正常波动中被洗出。

**影响**：频繁假止损，影响策略胜率。

**建议**：
- 添加 1% 缓冲：`close < ma20 * 0.99`
- 或使用 ATR 缓冲：`close < ma20 - atr * 0.5`
- 或要求连续 2 日跌破 MA20 才卖出

**当前状态**：保持敏感（风控优先），由 `trailing_stop` 模块提供更精细的止损管理。用户笔记强调"无论确定性多强，都必须设置止损"，敏感的卖出符合纪律要求。

#### P1-3 [系统架构师] 14:30 三个任务并行资源竞争

**问题**：14:30 同时执行 `scan_4`（盘中扫描）、`screener_1430`（尾盘选股）、`afternoon_flow_1430`（资金流报告），三者同时访问数据源。

**影响**：可能触发 API 频率限制，导致数据采集失败。

**建议**：将 `afternoon_flow_1430` 延后至 14:33 执行（数据采集 I/O 密集，不影响盘中扫描）。

**当前状态**：保持 14:30（用户明确要求），资金流报告使用 `run_in_executor` 线程池不会阻塞事件循环。API 频率限制由数据源三级冗余机制兜底。

### P2 级 — 后续优化

#### P2-1 [量化研究员] 缺少历史数据回测验证

**问题**：策略仅通过单元测试，未用 `backtest/engine.py` 验证历史表现。

**建议**：运行 `python scripts/run_backtest.py --symbol 600519 --strategy money_flow_follow --days 500` 验证策略收益/夏普/回撤/胜率。

#### P2-2 [量化研究员] 缩量递减条件过于严格

**问题**：`vol_shrinking` 要求连续 2 日严格递减（`volume[t-1] < volume[t-2] AND volume[t-2] < volume[t-3]`），实际市场中缩量回踩可能非严格递减。

**建议**：改为"前 N 日均量 < 前 N+M 日均量"的趋势性判断。

#### P2-3 [交易员] 未处理涨停板情况

**问题**：A 股创新高时可能是一字涨停板，无法买入。策略未检查涨停状态。

**建议**：在 `SignalPipeline` 过滤层添加涨停检查（已有 L3 风控 `涨跌停不交易`，但策略层可提前标注）。

#### P2-4 [数据工程师] 14:30 盘中资金流数据可能不完整

**问题**：14:30 时 A 股未收盘（15:00 收盘），东方财富 API 的盘中资金流数据可能不如收盘后准确。

**建议**：在卡片中标注"盘中实时数据，最终数据以 15:10 收盘日报为准"。

#### P2-5 [系统架构师] flow_report.py 代码重复

**问题**：`build_afternoon_card` 与 `build_close_card` 约 60% 代码重复（大盘概览、行业 TOP、重点行业、强流入个股格式化）。

**建议**：提取公共部分为 `_format_market_section()`、`_format_sector_top_section()` 等辅助函数。

## 总结

### 优势
1. **策略逻辑清晰**：5步复盘流程完整映射到过滤条件，每步有明确的量化定义
2. **风控优先**：卖出信号覆盖买入信号，符合"无论确定性多强必须止损"的纪律
3. **系统集成良好**：复用现有 Strategy ABC / SignalRouter / flow_report 基础设施
4. **决策报告实用**：14:30 报告包含操作原则提醒 + 资金方向判断 + 强势个股
5. **数据鲁棒**：NaN 保护 + 三级冗余数据源 + 缓存兜底

### 待改进
1. **"热点板块"近似**：个股涨幅 ≠ 板块涨幅，需在选股层补充板块筛选
2. **回测验证**：策略未经过历史数据回测，应在生产前完成回测
3. **卖出敏感度**：跌破 MA20 即卖出可能过于敏感，需结合 trailing_stop 模块使用
4. **代码重复**：flow_report 三个卡片构建函数有大量重复，应提取公共部分

### 第一性原理审视
- **alpha 来源**：策略的 alpha 来自"跟随资金强度 + 创新高回踩 + 放量确认"的组合，逻辑上合理（主力资金消化套牢盘后继续推升）
- **风险控制**：风控优先原则在代码层面得到落实（卖出覆盖买入）
- **可操作性**：14:30 推送决策报告，给用户 30 分钟操作窗口，时机合理
- **数据依赖**：策略仅依赖 OHLCV 数据，与 SignalRouter 兼容，不引入外部 API 依赖

> **结论**：策略实现符合用户笔记的核心观点，5步复盘流程完整落地。已修复 P0 级风控和配置问题，P1/P2 级问题有明确的改进路径。建议在生产运行前完成回测验证（P2-1）。
