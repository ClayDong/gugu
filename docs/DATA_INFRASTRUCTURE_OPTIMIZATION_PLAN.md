# gugu 数据基础设施优化与上线计划

> 版本：v1.0
> 制定日期：2026-08-18
> 目标：在不破坏现有信号监控、回测、风控和通知链路的前提下，提升数据源稳定性、可追溯性和另类数据可用性，并以真实数据和自动化测试作为上线门禁。

## 1. 第一性原理判断

### 1.1 真正的问题

gugu 当前的瓶颈不是“没有数据”，而是：

1. 同一数据源的请求、限流、重试和单位转换散落在多个模块；
2. 采集结果虽然有部分 `DataFrame.attrs`，但来源、时间、口径和质量状态没有形成统一证据链；
3. 另类数据采集器仍直接依赖 akshare，源站变化会把业务模块和上游实现细节耦合在一起；
4. 任何新增数据都可能被过早加入策略，导致把相关性误认为预测力；
5. 真实网络成功不能替代可重复测试，测试通过也不能证明线上数据源当前可用。

### 1.2 不变的核心原则

- 数据源是可替换基础设施，不是策略逻辑；
- 数据缺失时默认保守，不用空值伪装成中性数据；
- 真实数据必须带来源、采集时间、统计周期、单位和质量状态；
- 新因子先进入研究和观察，不直接进入生产策略；
- 所有切换都可回滚，旧链路必须保留；
- “上线”定义为：代码、测试、真实采集、降级、缓存、质量校验和运行记录均通过，而不是“接口能返回一次”。

## 2. 对抗性审查：最可能失败的地方

| 假设 | 反例 | 防线 |
|---|---|---|
| 东方财富接口长期可用 | 改字段、限流、封 IP | 统一传输层、缓存、退避、熔断、多源降级 |
| akshare 的字段永远稳定 | 上游网页改版 | 业务层不直接依赖函数细节；保留适配器和契约测试 |
| 龙虎榜/解禁/融资数据天然有预测力 | 数据只解释过去，不能预测未来 | 因子 IC、事件研究、Walk-Forward 通过后才可启用 |
| 返回非空就代表数据正确 | 单位错误、日期错位、复权混用 | 统一 evidence attrs + 质量校验 + 交叉抽样 |
| 单元测试通过即可上线 | 真实网络、证书、限流、源站字段会变化 | 真实 smoke test、降级演练、上线前运行记录 |
| 多源并发越快越好 | 并发触发源站风控 | 按数据源独立节流，批量接口优先，禁止无边界并发 |

## 3. 交付范围

### 3.1 本期必须完成

1. 建立共享的 HTTP 数据源传输层：复用 Session、统一请求头、最小间隔、指数退避、随机抖动、JSON 校验；
2. 将东方财富直连采集器改为使用共享传输层，保持现有公开方法和 DataFrame 列契约不变；
3. 统一数据证据链元数据：`data_source`、`fetch_timestamp`、`period`、`unit`、`adjust_type`、`quality_status`、`data_stale`；
4. 将龙虎榜、解禁等另类采集器的缓存与元数据纳入同一契约；
5. 增加单元测试、契约测试、模拟失败/限流测试和真实网络 smoke test；
6. 运行全量相关测试与真实采集，形成上线门禁记录。

### 3.2 本期明确不做

- 不整体重写 DataManager；
- 不引入新的收费数据源或密钥；
- 不把任何新增另类因子写入生产 `verified_strategies`；
- 不改变当前默认的 signal_only / track_live 安全边界；
- 不把 LLM 变成交易决策者；
- 不把非一手新闻/研报当作交易事实源。

## 4. 目标架构

```text
业务采集器
  ├─ 行情 Collector
  ├─ 资金流 Collector
  └─ 另类数据 Collector
          ↓
统一 Provider / Transport
  ├─ Session 复用
  ├─ 数据源级限流
  ├─ 指数退避 + 抖动
  ├─ 错误分类
  └─ 请求日志
          ↓
统一 Evidence Metadata
  ├─ 来源
  ├─ 采集时间
  ├─ 统计周期
  ├─ 单位 / 复权口径
  ├─ 新鲜度
  └─ 质量状态
          ↓
DataManager / FactorEngine / SignalPipeline
          ↓
研究验证 → validation_gate → 观察或生产
```

## 5. 分阶段执行

### Phase 0：基线与边界

- 记录工作区已有改动，不覆盖不相关修改；
- 运行数据层相关测试，建立基线；
- 确认现有 DataFrame 字段契约和缓存行为。

验收：基线命令有可保存输出；已有测试失败必须区分历史失败与本期引入。

### Phase 1：共享传输层

- 新增 `src/gugu/data/providers/http_transport.py`；
- 支持可注入 clock/sleep，便于测试；
- 对 429、5xx、网络异常做有限重试；
- 只对幂等 GET 重试；
- 不在 transport 层吞掉业务解析错误；
- 不记录 URL 中的敏感参数。

验收：传输层单元测试覆盖成功、空响应、HTTP 错误、重试、最小间隔和请求头。

### Phase 2：数据证据链

- 新增统一的 metadata helper；
- 所有共享传输层返回的数据由调用方补齐 period/unit/adjust_type；
- 过期缓存明确标记 `data_stale=True`；
- 数据不可用明确标记 `data_available=False` 和 `data_error`。

验收：同一数据块能回答“来自哪里、何时采集、是什么口径、是否过期、是否通过质量校验”。

### Phase 3：迁移另类数据

按风险和收益排序：

1. 龙虎榜；
2. 限售解禁；
3. 融资融券 / 大宗交易；
4. 其余另类因子。

迁移要求：先保留 akshare 适配器作为 fallback；新路径失败不能导致生产信号异常放行；新数据仍只用于研究/观察。

验收：每个采集器至少完成缓存命中、真实成功、异常降级和空数据拒绝四类测试。

### Phase 4：研究验证隔离

- 新增数据只接入研究输出和诊断报告；
- 因子必须经过横截面 IC、分层收益、交易成本和 Walk-Forward；
- 结果写入验证记录，不自动修改生产策略清单。

验收：没有验证记录的因子不能出现在生产启用列表；现有策略结果不因新增数据发生静默变化。

### Phase 5：真实运行与上线门禁

真实运行至少包括：

1. 真实历史 K 线采集；
2. 真实行业/个股资金流采集；
3. 真实龙虎榜或解禁采集；
4. 缓存二次命中；
5. 人为模拟主源失败并确认降级；
6. 人为模拟 stale cache 并确认标记；
7. 运行数据质量校验；
8. 运行相关单元、集成和回归测试；
9. 检查日志中无未处理异常和敏感信息。

## 6. 上线门禁

必须全部满足：

- [ ] 计划文档与实际实现一致；
- [ ] 新增代码通过 ruff；
- [ ] 新增/修改模块通过 mypy（若历史债务阻塞，必须明确列出）；
- [ ] 相关单元测试 100% 通过；
- [ ] 关键集成测试通过；
- [ ] 真实 smoke test 至少成功一次且记录来源/时间；
- [ ] 失败、限流、空数据、缓存和降级路径均有测试；
- [ ] 不修改现有生产策略准入状态；
- [ ] 不产生自动下单行为；
- [ ] 运行产物和缓存不进入 Git；
- [ ] 可通过关闭新 provider 配置回滚到旧路径。

## 7. 回滚方案

1. provider 配置开关关闭新路径；
2. 保留旧 akshare / eastmoney 适配器；
3. 清理本期新增的运行缓存，不删除历史业务数据；
4. 重新运行基线测试和真实 smoke test；
5. 若出现数据口径不一致，宁可返回不可用并告警，不使用未确认数据。

### 8.2 尚未满足的上线阻断项

- [ ] push2/push2his 的真实历史 K 线、行业资金流和个股资金流 smoke test：当前执行环境的代理拒绝 `push2his.eastmoney.com` 连接，返回 `ProxyError/RemoteDisconnected`；这不是通过 fallback 伪造成功，需在允许访问上游的网络环境重新执行；
- [ ] 全项目 `mypy`：当前环境的 NumPy stub 报 `Type statement is only supported in Python 3.12 and greater`，阻断发生在第三方 `numpy` stub，目标新增模块自身已通过；建议统一 mypy/Python/numpy 版本后重跑；
- [ ] 生产可配置的新 datacenter provider 开关和旧路径回滚开关：当前新 Collector 保持研究/诊断隔离，未注册进生产因子引擎，回滚通过“不启用新路径”实现；若要正式运营需补显式配置项和启动自检；
- [ ] 龙虎榜日期过滤已通过真实上游验证为单引号 DSL，代码已固定该语法；仍建议将更多报告的日期/单位校验加入 smoke test，避免东财 DSL 或字段漂移；

### 8.3 当前上线结论

本期代码和测试质量门禁通过，但真实行情/资金流网络门禁未通过，因此当前结论是：**可进入受控观察和研究验证，不宣称达到生产上线标准**。在可访问东财 push2/push2his 的网络环境完成 K 线与资金流 smoke test、统一类型检查环境并记录结果后，才能重新评估上线。
