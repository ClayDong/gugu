核心判断：当前“断板反包”不是一个已经被证实的独立自动化策略。问题不是简单的“多加几个指标”就能修复，而是博主的交易对象更接近“高辨识度标的 + 盘中承接/资金状态 + 题材情绪 + 执行纪律”的条件组合；项目当前主要用日线 OHLCV 近似，复刻了形状，尚未复刻决策信息。
重要纠偏：项目历史材料曾把“高活跃老妖”视为唯一正因子，但后续 500d 长历史审计已将该结论降级为“微弱且不显著”；较稳定的增量线索反而是入场时点/次日开盘溢价过滤，但其 Walk-Forward 仍不显著，不能直接写入生产策略。

一、为什么当前效果不合适

1. 策略身份发生了漂移

项目里至少存在三种“陈学长”实现：chenxuezhang六类均线/量价规则；rebound_system完整断板反包手册；breakout_rebound旧版反包实现。它们不是同一个策略，不能用一个名称下的回测结果证明博主方法有效或无效。

2. 代码只观察日线收盘形态

博主口中的“承接、砸盘、护盘、盘口强弱、板块助攻、资金来了没有”，都可能在盘中完成。当前实现把它们压缩为收盘价、最高最低价、成交量和均线，信息损失不是参数问题，而是观测变量缺失。

3. 买入价格存在不可交易近似

事件研究常用“事件日收盘价近似可成交”，而完整脚本注释明确承认无法模拟分钟、盘口和涨停队列。反包日可能买不到，次日开盘可能高开透支，低吸也可能只在盘中瞬间触价。形态收益不等于可实现收益。

4. 研究样本与生产策略不一致

历史报告使用67只主板活跃题材股、约2.5年；闭环文件只有28笔交易；生产持仓审计则是1105只主板中抽样100只、500d。不同股票池、不同入场、不同出场、不同持仓模型混在一起，结论不能直接横向比较。

5. 失败并非只来自“规则太松”

当前规则在不断收紧：一字板、连板、前20日涨停、实体阴线、首板成交额、护盘破位等都已加入。但 rebound_full_results.csv 仍显示买点A闭环均值为负，说明至少有一部分损失来自买点本身和不可见的市场语境，而不只是误检。

6. 统计显著不代表交易可赚

项目审计已经验证：事件研究看起来显著的策略，进入标准持仓回测后可能转负。陈学长主策略持仓审计为均值 -0.22%、Sharpe -0.24、最大回撤 -20.23%。这条审计经验必须优先于单一 p 值。

二、已有真实结果：不要被“漂亮子集”带偏

闭环结果来自 data/rebound_full_results.csv；收益已包含脚本中的成本设定。A 的19笔、C 的9笔不是充分样本。
项目验证报告的152事件结果：买点A 112笔，买点C 40笔；这是裸持有事件研究，不等于同一批样本的闭环结果。
证据层结果应如何解释
断板反包事件研究买点A 5日 -0.86%，N=112，p=0.044；买点C 5日 -0.67%，N=40，p=0.480A 的负向证据较强；C 不是“有效”，只是当前样本下未检出稳定优势。
闭环持仓文件A N=19、均值 -2.89%；C N=9、均值 +3.49%C 的正收益不能抵消样本过小；A 的止损触发占比高，买点和执行需要重做。
高活跃子集历史报告中“涨停≥20 + 买点2”16例，5日 +4.08%，p=0.357漂亮但不显著，且收益依赖2024；只能作为研究假设，不能作为生产条件。
Walk-Forward / 优化报告breakout_rebound 样本外 Sharpe=0，passed=false未通过准入门禁，不能启用。
陈学长持仓审计13,430笔，均值 -0.22%，SharPE -0.24，最大回撤 -20.23%当前六类规则混合实现不足以复刻博主的正收益；“保持 enabled”的旧结论应重新审查。

三、先把“博主方法”拆成四层

硬条件 可以直接量化

  • 连续涨停/断板的定义、断板距首板的交易日数
  • 收盘是否跌破首板开盘价、是否出现实体阴线
  • 成交量相对首板量、MA5/MA20 的比例
  • 反包是否突破洗盘日高点、涨幅和成交额
  • 次日开盘溢价、买入可成交性、涨跌停限制

软条件 应做评分而非一票否决

  • “有辨识度”“强承接”“洗得干净”“位置舒服”
  • 板块联动强度、龙头/中军/跟风层级
  • 市场情绪处于分歧、修复、高潮还是退潮

语境条件 需要额外数据

  • 公告/新闻发布时间与题材是否真实扩散
  • 集合竞价金额、开盘后5/15/30分钟成交结构
  • 封单、撤单、炸板、回封、主动买卖方向
  • 板块当日涨停家数、核心股表现和负反馈

事后解释 不能直接回填成规则

  • “主力洗盘”“主力护盘”“这里有人在做”
  • 只在成功案例出现的“某个细节”
  • 无法在当时刻观察、只能收盘后确认的叙述

判断标准：如果一个条件无法在交易时刻冻结、无法给出原始数据字段、无法被另一位研究员复算，就不能直接成为生产因子。

四、LLM + Prompt 能不能做？能，但只能放在“语义抽取/审计层”

推荐边界：LLM 不输出“买/卖”，不输出仓位，不改变阈值；LLM 只把当时可获得的文本和结构化行情转成固定枚举标签，最终由规则引擎和 Walk-Forward 数据裁决。
用途可行性正确用法风险
新闻/公告题材归因较适合输入发布时间≤T的文本，输出题材类别、直接性、扩散证据、时效性。不能让模型看到T之后的标题、涨幅或结果。
板块语境标签可研究先由确定性程序统计涨停/跌停/连板/核心股，再让LLM解释标签。“主线/退潮”容易受措辞影响，需固定枚举与人工抽样。
分时形态描述依赖分钟数据输入冻结的5/15/30分钟摘要或图像快照，输出承接/冲高回落等标签。当前项目缺少完整分钟/盘口数据，不能先假设可做。
直接生成交易规则不推荐只能作为研究假设生成器；生成后必须人工固化、版本化、独立样本验证。容易把博主事后叙事过拟合成条件，且历史重复调用可能不稳定。

建议的冻结 JSON

{
  "asof": "T 盘中/收盘时刻",
  "source_ids": ["公告/新闻ID"],
  "theme_state": "主线|支线|孤立|未知",
  "theme_strength": "强|中|弱|未知",
  "board_role": "核心|中军|跟风|未知",
  "intraday_acceptance": "强|中|弱|未知",
  "wash_quality": "有效|存疑|无效|未知",
  "uncertainty": 0.0,
  "evidence_spans": ["原文片段或字段引用"],
  "model_version": "固定版本",
  "prompt_version": "固定版本"
}

任何标签都必须同时记录：输入数据截止时间、模型版本、Prompt 版本、原文证据、置信度和“未知”状态。缺数据不能默认“中性通过”。

五、推荐的验证路线

  1. 策略身份归一化：把 chenxuezhang 六规则、rebound_system 断板反包手册、breakout_rebound 旧实现分别命名，禁止再共用“陈学长策略”总称。
  2. 纯量化基线：只用 T 日及以前的日线，统一次日开盘/收盘成交口径，加入涨停买不到、低开、高开、滑点、佣金、印花税和 T+1。
  3. 样本扩展与事件去重：覆盖至少3-5年、主板全市场，按股票和事件链去重；报告原始事件数、可交易事件数、最终成交事件数。
  4. 先验证硬条件：对首板、洗盘、支撑、反包、开盘溢价逐个做 IC、分层收益和事件研究；不以组合整体的漂亮结果替代单因子证据。
  5. 做真实持仓回测：以策略真实信号串联交易，不能只看独立 5/10 日窗口；报告收益、Sharpe、回撤、胜率、盈亏比、交易容量。
  6. 再引入语义标签：先人工标注一小批 T 时刻样本，LLM 做离线抽取；测试重复调用一致性、人工一致性、不同市场状态稳定性和信息泄漏。
  7. Walk-Forward 冻结：Prompt、标签字典、阈值、权重都在训练期冻结；验证期只运行，不允许根据结果改 Prompt。
  8. 生产门禁：只有独立样本外超额为正、成本后期望值为正、回撤可接受、参数/标签稳定、纸面盘达到规定信号数后，才可进入 experimental；未通过就保持 disabled。

六、当前项目的最终建议

保留

  • 破位止损作为风险纪律，继续单独验证。
  • 板上减半作为持仓管理假设，不当作入场 alpha。
  • 开盘溢价作为研究因子，但暂不生产化。
  • 完整证据链：规则版本、数据截止时间、成交假设、结果文件。

暂不做

  • 不把“老妖股+反包追涨”16例正收益当成已证实策略。
  • 不把LLM生成的规则直接写入策略。
  • 不使用项目里暴露的 DeepSeek API key；该密钥已出现在源码中，应立即轮换并从代码移除。
  • 不恢复 disabled 策略，不产生自动下单。
一句话结论：陈学长可能确实有能力，但“他能做”与“当前日线代码能复刻他的决策”是两件事。最合理的工程路线不是让 LLM 直接猜买点，而是用 LLM 把“题材、承接、辨识度、情绪”等隐含判断变成可审计标签，再让数据和样本外验证决定它有没有价值。
